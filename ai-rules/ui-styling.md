# ui-styling.md

## UI Styling Notes
- `docs/plans/quiet-agenda-ui/{prompt,documentation}.md` define the current presentation contract; initial-release requirements still govern scheduling and authorization. Load both plans through `rule-loading.md`; no separate `DESIGN.md` or design-lint tool exists.
- Existing UI is implementation evidence, not design precedent. When it conflicts with the approved UI contract, migrate toward the contract instead of preserving the rejected treatment.
- Reuse helpers only when they express approved tokens and component behavior; remove or rename helpers tied to superseded directions.
- Use native macOS controls, system typography, semantic colors, and the approved Deep Sapphire tokens in `AgendaPalette` (Quiet Agenda `DEC-3`). Keep focus and selection distinct; support keyboard access, VoiceOver, and light/dark appearance.
- Keep the daily editor proportional to this utility: independent startup/shutdown switches and time pickers, Apply, and truthful current-system state. Disabled switches disable their pickers.
- Use native scrolling and confirmation dialogs. Require explicit confirmation for replacing unrepresentable schedules, enabling account automation, and removing the helper; preserve the system-managed authorization UI.
- App artwork is generated by `Tools/generate_icon.swift`; no game-specific fonts, monument assets, or custom modal/scroller system apply.
- Avoid introducing macOS APIs newer than the deployment target unless availability-guarded.
- Keep SwiftUI views readable and split reusable styling into small view modifiers or helpers when the same pattern appears more than once.
